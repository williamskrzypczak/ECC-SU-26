Sprint 1: Trello Boards and Sprint Review

Introduction

This module provides official guidelines for your team Trello project board and your Sprint 1 review presentation. The goal is a consistent, professional Agile workflow. This structure helps you stay organized, track work, and present progress clearly.

Trello is your team dashboard. The sprint review is your demo day. The board shows what you planned and finished. The presentation shows working software — not a status email.

Learning Objectives

After completing Sprint 1, you will be able to:

  • Set up a Trello board using the required list structure
  • Write user stories and acceptance criteria on Trello cards
  • Move work through Product Backlog → Done with clear ownership
  • Deliver a 7-minute sprint review that demos working SwiftUI features

Trello Project Board Setup

Your Trello board is the central hub for the project. It shows your workflow and tracks progress. All teams must set up their board as follows.

Board naming convention

Name your board using this format:

[Course Code] - [Project Name] - [Team Name]

Example: MAD-157 - Campus Hub App - Team Alpha

Required lists (columns)

Your board must have these five lists in this order:

  1. Product Backlog — Master list of all tasks, features, and user stories for the entire project.
  2. Sprint Backlog — Items your team commits to for this sprint, moved from the Product Backlog before the sprint starts.
  3. In Progress — Tasks actively being worked on. Only assign work here when someone has started it.
  4. In Review / Testing — Completed tasks waiting for teammate review, test, and approval.
  5. Done — Reviewed, verified, and accepted work for the current sprint.

Card (task) structure

Each card represents one task or user story and must include:

  • Card title — Clear, concise task name (example: Build RSVP sheet UI)
  • Description with:
    • User story: As a [user type], I want [an action] so that [a benefit].
    • Acceptance criteria: Bulleted list of conditions for Done (example: Sheet opens from Home tab, User can submit RSVP)
  • Members — Assigned teammate(s)
  • Labels — Required labels: Feature, Bug, UI/UX, Backend, Documentation. Add SwiftUI or Xcode when relevant.
  • Checklist — Use for complex tasks broken into sub-steps

Sprint Review Presentation Structure

The sprint review is a formal demo of working software built during the sprint. It is not a status report. Follow this slide structure for consistency.

Target time: 7 minutes total.

Sprint review slide structure
Slide Content
1 — Title Project name, team name, sprint number (example: Sprint 1 Review), and date
2 — Sprint goals Bullet list of high-level goals (example: Implement tab navigation, Build RSVP sheet)
3 — What was completed Screenshot of the Done column from your Trello board. List key features or user stories completed.
4 — What was not completed (and why) Items left in Sprint Backlog or In Progress. Give a brief, professional reason for each. Transparency matters.
5 through N — Live demonstration Demo working software in the simulator or on device. Do not show code or static mockups. Walk through completed user stories from a user perspective. Each teammate demos work they contributed.
N+1 — Key learnings and metrics What the team learned (technology, collaboration, challenges). Include a simple metric (example: 8 of 10 stories completed).
N+2 — Goals for the next sprint High-level goals for Sprint 2 to show forward planning
Final — Q&A Open the floor for questions from the instructor and classmates

Your recorded video must include at least slides 1 through 8 worth of content: title, goals, completed work, incomplete work, live demo, learnings, next sprint goals, and Q&A (even if Q&A has no audience questions, state that the floor is open).

Deliverables

  • Trello board set up with the five required lists and at least four sprint cards
  • Sprint review video (~7 minutes) covering the slide structure above
  • Screenshot of your Trello Done column for Sprint 1
  • links.txt with your Trello board link and video link (if the video is hosted outside Canvas)

Grading Rubric

Sprint 1 grading criteria (100 points total)
Criterion Points
Trello board follows naming, lists, and card structure 30
Presentation includes all required sections (slides 1–8 content) 25
Live demo shows working SwiftUI software (not code or mockups only) 30
Professional communication — clear goals, honest blockers, team participation 15

Troubleshooting

Trello board is missing a required list

Add the list and drag cards into the correct column. Match the exact list names in this module.

Video is too long

Cut repetition in the demo. Keep slides 1–4 and the final sections brief so most time goes to the live demonstration.

Video file is too large for Canvas

Upload to Canvas Studio or an unlisted host. Put the view link in links.txt and note that in your Canvas comment.

No working features to demo yet

Demo the smallest working slice (one screen, one flow). Explain blockers on slide 4 and show your plan for Sprint 2.

How to Submit on Canvas

Package your work as one zip file. Use the exact structure in the Sprint 1 submission guide.

Create your zip on a Mac

  1. Create a folder (example: sprint1-smith-jane).
  2. Add links.txt, your video file (if required in the zip), and a screenshots/ folder with trello-done-column.png.
  3. Right-click the folder and choose Compress "folder name".
  4. Rename the zip to sprint1-lastname-firstname.zip and upload to Canvas.

See the full Mac zip instructions if you get stuck.
