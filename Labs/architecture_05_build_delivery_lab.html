Architecture Lab 5: Build and Delivery

This is step 5 of 7. Plan on about 40 minutes with your team.

Introduction

You already know what the app shows, decides, saves, and locks. This lab is about how a change leaves the team.

You will draw four stops from Build to Ship in the same Figma file.

Work with your team for about 40 minutes. Then each person turns in their own zip.

Use the same Figma link as the earlier labs. Your reflection must be your own words.

Learning Objectives

After this lab, you will be able to:

  • Name what must be true before a change can leave the team
  • Name who is allowed to press ship
  • Explain how a user gets the new version
  • Explain how you go back if the new version breaks

Key Ideas

Build and Delivery is the kitchen pass. A dish is not done when the cook says so. It is done when it leaves the window and reaches the table.

A change on your laptop is not a change on someone else’s phone. Something has to carry it there.

Prerequisites

Finish Figma Basics. Your team needs a project you can describe in one sentence.

You need a free Figma account. Create one at figma.com/signup if you do not have one yet.

Lab Instructions

Part 1: Talk through the questions

Read these out loud. Answer them for your app, not for a sample app. Give this about 8 minutes.

  1. What must be true before a change is allowed to leave the team?
  2. Who is allowed to press ship?
  3. How does a user actually get the new version?
  4. If the new version breaks, how do you go back?

Part 2: Build the frame

Give this about 25 minutes. A classmate should understand the frame in 60 seconds.

  1. Open the same team file. Do not start a new file.
  2. Add a wide frame. Name it 5 Build and Delivery.
  3. Draw four boxes left to right: Build, Test, Review, Ship.
  4. Put your app name above the line.
  5. Under Test or Review, write one check that must pass.
  6. Under Ship, add a note that says how you go back if the new version breaks.

Your frame is done when it has all of these:

  • Four stops in a line: Build, Test, Review, Ship
  • Your app name on the line
  • One check written under Test or Review
  • A short go-back note under Ship

Part 3: Share and export

  1. Click Share in the top right.
  2. Set access to Anyone with the link can view.
  3. Copy the link. You will paste it in links.txt.
  4. Select the frame named 5 Build and Delivery.
  5. In the properties panel, scroll to Export. Click +. Choose PNG at 1x.
  6. Export the frame. Save it as architecture-5-build.png.

Put that PNG in a folder named screenshots. The file name must match exactly.

Reflection Questions

Answer in your own words. Write at least two sentences for each question. Do not copy a teammate.

  1. What must be true before your team ships a change?
  2. Who is allowed to press ship?
  3. How does a user get the new version, and how do you go back?

Deliverables

Submit one zip file named architecture5-build-lastname-firstname.zip. The team may share one Figma link. Each student still writes their own reflection.

  • links.txt with one line: Figma: and your view link
  • reflections.txt with Q1:, Q2:, and Q3:
  • screenshots/architecture-5-build.png

Troubleshooting

Share link asks people to log in

Click Share. Set access to Anyone with the link can view. Copy that link into links.txt.

The export is blank or cropped

Select the outer frame named 5 Build and Delivery. Do not select a text box inside it.

Ship is the first box

Build and test come first. A user should not be the first person to find a break.

Go back says “we will figure it out”

Write one plain step. Keep the old version, or pull the new one back.

How to Submit on Canvas

Package your work as one zip file. Use the exact names in the Architecture Lab 5 submission guide.

Create your zip on a Mac

  1. Create a folder named architecture5-build-lastname-firstname.
  2. Put links.txt, reflections.txt, and the screenshots folder inside it.
  3. Right-click the folder and choose Compress.
  4. Rename the zip if needed, then upload it to this Canvas assignment.

Compress the folder, not the loose files. See the Mac zip steps if you get stuck.
