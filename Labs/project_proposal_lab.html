Project Proposal Assignment

Purpose

Propose your own SwiftUI iOS app for the course capstone. Define the problem, users, features, data, and how you will know the app succeeds. Your proposal must show that you can apply the major concepts from this course (Chapters 1 through 7, plus data and services from Chapters 14–15). The goal is to demonstrate understanding by designing a feasible app you could build in Xcode.

Think of this as a blueprint, not the house. You are not building the full app yet. You are explaining what you would build, why it matters, and which course skills each part of the app will use.

Concept Coverage Requirement

Your proposal must explicitly address or plan to use the concepts below. Include a Concept coverage section (see Required sections) where you state how your project uses each.

Chapter 1: SwiftUI Development Environment

  • What is SwiftUI? (declarative UI built in Swift)
  • App structure: @main app file, WindowGroup, and primary views
  • Xcode tooling: previews, simulator, and project organization
  • How you will use GitHub (or similar) to track your capstone work

Chapter 2: Basic UI Elements and Layouts

  • Layout stacks you will use (VStack, HStack, ZStack)
  • At least two reusable view components (custom structs or subviews)
  • Spacing, padding, alignment, or Spacer in your screen designs

Chapter 3: Adding Interactivity

  • State management with @State or related patterns
  • At least one user control (button, toggle, picker, or text field)
  • How user input changes what appears on screen

Chapter 4: Scrollable Views and Lists

  • A scrollable screen using ScrollView, List, or ForEach
  • What data drives the list (sample items, categories, or search results)
  • Search, sections, or keyboard handling if relevant to your app

Chapter 5: Grids

  • A grid-based screen using LazyVGrid, LazyHGrid, or a static Grid
  • If grids are not central to your app, explain why and where a grid still fits (catalog, gallery, schedule)

Chapter 6: Tab Bars and Modal Presentation

  • Main navigation pattern: TabView and/or modal presentation (.sheet, .alert, or popover)
  • Which tasks belong in a tab vs a temporary modal

Chapter 7: Navigation

  • Navigation with NavigationStack (or equivalent for your iOS target)
  • At least one drill-down flow (list → detail) or programmatic navigation
  • Toolbar actions or secondary screens (settings, about, help)

Chapter 8: Data, Services, and Wrapping Up

This section maps to advanced course topics (SwiftData, REST, Firebase) and project completion.

  • Data strategy: local persistence (SwiftData), cloud (Firebase), and/or REST API — state which you will use and why
  • Problem definition and success criteria (how you will measure success)
  • Impact or “what if it works well?” (who benefits and why the app matters)
  • Optional: Figma wireframe reference, TestFlight, App Store steps, or accessibility plan

Required Proposal Sections

Use the following structure. Write in clear, concise prose. Headings in your document should match these section names.

  1. Problem statement — What question or goal does the app address? Who is the user? Why does it matter?
  2. Data — Data sources (user input, local storage, API, Firebase). Approximate entities or models. Known limits (offline use, privacy, sample vs live data).
  3. Methods — Planned screens, SwiftUI patterns, and architecture. Describe how they align with Chapters 2–7 and your data choice (Chapter 8). Include a brief screen-flow sketch (tabs → lists → detail) so navigation and modals are clear.
  4. Evaluation — How you will test the app (preview, simulator, manual test checklist). Success criteria and what “done” looks like for the capstone.
  5. Concept coverage — For each chapter (1–8), write one or two sentences explaining how your project uses the required concepts. You may use a checklist plus short narrative.
  6. Timeline or milestones (optional) — High-level phases (wireframe, core screens, data layer, polish, testing).
  7. References or resources (optional) — Apple docs, Figma file, API docs, or tutorials you plan to use.

Deliverable and Format

Project proposal deliverable requirements
Item Requirement
Deliverable A single project proposal document inside one zip file
Format Markdown (proposal.md) or PDF (proposal.pdf). Use headings that match the required sections.
Length 800–1200 words (about 2–4 pages), not including references
Submission Submit via Canvas as specified below

Tip: Start from the campus app labs if you need inspiration. Your capstone should go further — a distinct app idea with a clear user and purpose.

Grading Rubric

Project proposal grading criteria (100 points total)
Criterion Points
Clarity of problem — goal, user, and motivation are clear 25
Feasibility — scope, data, and SwiftUI methods are realistic for the term 25
Concept integration — required concepts from Chapters 1–8 are addressed completely 30
Evaluation plan — testing approach and success criteria are appropriate 10
Writing quality — organized, concise, and free of major errors 10

Deliverables

  • proposal.md or proposal.pdf with all required sections
  • Word count within 800–1200 words (excluding references)
  • Concept coverage for Chapters 1–8

How to Submit on Canvas

Package your work as one zip file. Use the exact structure in the Project Proposal submission guide.

Create your zip on a Mac

  1. Create a folder on your Desktop named for the assignment (example: project-proposal-smith-jane).
  2. Place proposal.md or proposal.pdf inside the folder.
  3. Right-click the folder and choose Compress "folder name".
  4. Rename the zip if needed (example: project-proposal-smith-jane.zip).
  5. Upload the zip to the Canvas assignment.

See the full Mac zip instructions if you get stuck.
