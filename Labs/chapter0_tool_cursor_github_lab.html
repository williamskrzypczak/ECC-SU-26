Chapter 0 Lab: Cursor and GitHub

Introduction

You already used GitHub with Xcode. Now you will do the same jobs inside Cursor. Clone, commit, branch, push, pull, and merge without opening Terminal.

Cursor’s Source Control panel is a remote control for GitHub. You can finish this lab in about 15 to 20 minutes.

Use Cursor menus and the Source Control sidebar only. Do not use Terminal. Do not ask the AI Agent to run Git for you in this lab.

Learning Objectives

After completing this lab, you will be able to:

  • Sign in to GitHub from Cursor
  • Clone a GitHub repo and open it in Cursor
  • Stage, commit, push, and pull changes from Source Control
  • Create a branch, make a change, and merge it back to main

Key Ideas

Cursor’s Source Control panel is a remote control for GitHub. Clone downloads a copy of the project. A branch is a side road where you try an idea. Merge brings that idea back to the main road.

Push sends your work up. Pull brings new work down. Same ideas as the Xcode GitHub lab. New buttons live in Cursor.

Git actions inside Cursor
Action What it does Where to look
Clone Download a GitHub repo to your Mac Command Palette → Git: Clone
Commit Save a snapshot with a short message Source Control message box
Push Upload your commits to GitHub Source Control or status bar Sync
Pull Download commits from GitHub Source Control or status bar Sync
Branch Start a side road for a new idea Status bar branch name
Merge Bring the side road back into main Command Palette → Git: Merge Branch

Prerequisites

  • Cursor installed on your Mac
  • A free GitHub account
  • Finish Chapter 0: GitHub and Xcode Source Control first
  • Your public GitPractice repo from that lab (or another small public practice repo)

Lab Instructions

Part 1: Sign in to GitHub in Cursor

Topics: Cursor account and GitHub access.

  1. Open Cursor.
  2. Open the Command Palette with Cmd+Shift+P.
  3. Type Sign in to GitHub and choose the sign-in command that appears.
  4. Finish the browser login. Return to Cursor when it says you are signed in.
  5. Click the Source Control icon in the left sidebar (it looks like a branch).

Take a screenshot that shows you are signed in to GitHub in Cursor (Settings / Accounts, or a Source Control view that shows your GitHub account). Save it later as cursor-github-signed-in.png.

Part 2: Clone your repo and open it

Topics: Clone and open a folder.

  1. On GitHub.com, open your GitPractice repo. Click the green Code button. Copy the HTTPS URL.
  2. In Cursor, press Cmd+Shift+P. Type Git: Clone and choose it.
  3. Paste the repo URL. Choose a folder on your Mac (Desktop is fine).
  4. When Cursor asks, choose Open so the cloned folder becomes your workspace.
  5. Confirm you can see project files in the Explorer sidebar.

Take a screenshot of Cursor with the cloned project open. Save it later as cursor-clone-open.png.

Write your public repo URL in links.txt (one line), for example https://github.com/your-username/GitPractice.

Part 3: Make a small edit and commit

Topics: Stage and commit.

  1. Open README.md. If it is missing, create a new file named README.md in the project root.
  2. Add one short line, such as: Edited in Cursor for MAD 157.
  3. Save the file (Cmd+S).
  4. Open Source Control in the left sidebar.
  5. Under Changes, click the + next to the file to stage it (or stage all changes).
  6. Type this commit message: Add Cursor lab note to README.
  7. Click Commit.

Write every commit message you use in this lab into commit-messages.txt, one message per line.

Part 4: Push to GitHub

Topics: Push local commits online.

  1. In Source Control, open the … menu (or use the status bar Sync / Publish controls).
  2. Choose Push. If Cursor offers Sync, that is fine too when it includes Push.
  3. Open your repo on GitHub.com. Confirm the new commit message appears.

Take a screenshot of Source Control (or GitHub.com) showing your new commit. Save it later as cursor-commit.png.

Part 5: Create a branch and commit on it

Topics: Branch as a side road.

  1. Click the branch name in the lower-left status bar (it often says main).
  2. Choose Create new branch….
  3. Name the branch add-note. Press Return.
  4. Confirm the status bar now shows add-note.
  5. Edit README.md again. Add a second line, such as: Branch practice note.
  6. Save, stage, and commit with the message: Add note on add-note branch.

Take a screenshot that shows the add-note branch name and your new text. Save it later as cursor-branch-commit.png.

Part 6: Merge back to main and push

Topics: Merge and push.

  1. Click the branch name in the status bar. Switch back to main.
  2. Press Cmd+Shift+P. Type Git: Merge Branch and choose it.
  3. Select add-note. Confirm the merge.
  4. Open README.md. Confirm both of your new lines are on main.
  5. Push to GitHub.
  6. On GitHub.com, confirm main shows the merged text.

Take a screenshot of the merged README.md on main in Cursor or on GitHub.com. Save it later as cursor-merged-main.png.

Part 7: Pull a change from GitHub

Topics: Pull downloads remote edits.

  1. On GitHub.com, open README.md and click the pencil to edit.
  2. Add one more line, such as: Pulled into Cursor.
  3. Commit the change on GitHub.com.
  4. Return to Cursor. In Source Control, choose Pull (or Sync).
  5. Confirm the new line appears in your local README.md.

Troubleshooting

Sign in keeps failing

Use the Command Palette sign-in again. Finish the browser page fully. Then reopen Source Control.

Clone asks for a password

Use HTTPS and sign in with GitHub in the browser when Cursor prompts. Do not invent a Terminal password for this lab.

Commit button is gray

Save the file first. Stage the change with the + icon. Type a commit message, then click Commit.

Wrong branch selected

Look at the lower-left status bar. Click the branch name to switch. Merge only after you are on main.

Push rejected

Pull first, then push again. If Cursor shows a conflict, stop and ask your instructor.
