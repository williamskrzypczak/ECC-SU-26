Chapter 0 Instructor Key: Git Decisions

Use this page while groups work. Do not print it with the student cards. The student page is Chapter 0 In-Class: Git Decisions.

Desired Results

Students should leave able to say these five ideas in plain language:

  1. Commit is not a backup. It saves a snapshot on this Mac. GitHub does not have it until they push.
  2. Push and pull go opposite ways. Push is Mac to GitHub. Pull is GitHub to Mac.
  3. main is the copy they would show a client. Experiments go on a branch, then merge, then push.
  4. Edits on GitHub.com do not appear in Xcode until they pull.
  5. Uncommitted work blocks merge. Commit or discard first.

If a group still says “just save it to GitHub” for every card, they have not split commit from push. Stay with Cards A and B until that clicks.

Answer Key

Correct move, why it works, and what to listen for
Card Correct move Why Wrong move Listen for
A Commit, then push Xcode has the new text. GitHub does not. Commit writes the snapshot on the Mac. Push uploads it. Only commit leaves the website old. Only push with nothing committed leaves GitHub old. Local versus online, or phone versus iCloud
B Pull The new README lives on GitHub. Pull downloads it. Push tries to upload the old file. It can fail or fight the website copy. The website is ahead of my Mac
C Make a new branch, then edit there main stays the working app. The tagline is a draft. Edit main and a bad tagline is now in the copy they would demo. Draft thread. Do not break the good version.
D Merge into main, then push Switch to main, merge, then push. Merge is local. GitHub needs a push. Merge and stop. GitHub main stays old. Stay on the branch forever and main never gets the work. Merge is on the Mac. GitHub needs a push.
E Pull, then push GitHub has commits the Mac does not. Pull first, then push. Same as the lab troubleshooting note. Keep pushing. It keeps getting rejected. Download their change first
F Stop and commit (or throw away) leftover changes first Git will not merge while there is unfinished work. Then merge. Ignore leftover files. They get stuck or mix half-finished edits into main. Finish or undo the current edits first

Exit Tickets

They got it

  • A commit is on my Mac. A push is sending that save to GitHub.
  • I use a branch so that if my idea is bad, main still works.

Not there yet

  • Commit and push are the same.
  • Pull is how I upload.
  • A branch is a second GitHub account, or a copy of Xcode.

Debrief Script

Ask the whole class. Do not open Terminal. Do not introduce pull requests today.

  1. After Card A, is your work safe if the laptop dies? Only if they pushed.
  2. After Card B, who has the newest README, the Mac or GitHub? GitHub, until they pull.
  3. If the tagline was ugly, who still has a clean app? Anyone who used a branch.

If a Group Is Lost

Use one analogy only. Google Docs. Commit is a named version on this computer. GitHub is the file in Drive. Push is upload. Pull is download. Branch is “Make a copy” before a messy rewrite.

If they finish early, have them rewrite one bad commit message. Change update or fix stuff into a lab-style message such as Add my name to welcome screen.
